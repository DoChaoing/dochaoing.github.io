给 Agent 设定目标：验收标准与自动循环

2026-11-19 • AI 应用实战

对 Agent 说"帮我把这个功能做好"，得到什么全凭运气。Agent 时代的第一个技能是把愿望翻译成可验证的目标：模型自己判断是否达成、自己发现偏差、自己迭代。

完成标准必须是机器可判定的

对比两种说法：

愿望型："给博客加上 RSS，要好用"
目标型："用 hexo 生成 RSS；验收标准：
        1. hexo generate 无报错
        2. public/ 下存在 atom.xml
        3. XML 能通过 xmllint 校验"

目标型 prompt 让"完成"不再靠模型自我感觉——它有明确的检查清单，做完逐条验证，不通过就修。最好用的验收标准是现成的命令：测试套件、构建脚本、lint。项目里已有这些设施时，只要说"完成的标准是这些命令全部通过"，模型就会自己跑、自己循环修复。

三层目标设定

第一层：一次对话内的目标。 把验收标准写进 prompt 本身，配合 Plan Mode 先对齐步骤。小任务到此为止。

第二层：项目级目标。 长期有效的标准写进 CLAUDE.md——"本项目所有改动完成后必须通过 npm test"，让每次会话自动继承这个底线。

第三层：自动循环。 目标明确后，允许 Agent 无人值守迭代：

  • 会话内：明确说"循环执行直到测试全部通过，中途不需要问我"；
  • Stop 钩子：在 settings.json 里配置 Stop 事件，模型每次想结束时跑一次验收脚本，不达标就把失败信息塞回去强迫继续；
  • 无头模式：claude -p "修复失败的测试，直到全部通过"，跑在脚本或 CI 里，退出码即成败信号。

无头模式让 Agent 变成可编排的一环：

# CI 里：构建失败就让它自己修
npm test || claude -p "根据上面的报错修复测试，直到 npm test 通过" --max-turns 20

目标之外，护栏也不能少

自主循环的 Agent 权限越大，越需要约束：

  • deny 列表挡住绝对不许碰的操作（git push --force、删除文件）；
  • 循环上限：--max-turns 或任务描述里写明"最多尝试 5 轮，仍失败就停下来报告"；
  • 循环检测：让它在"连续两次改动没有任何测试状态变化"时停止——死循环及时止损也是目标达成的一部分。

拆解长目标

"把博客从 Hexo 迁移到 Astro"这种大目标，直接扔给 Agent 会失控。做法是拆成机器可判定的小目标链：

1. 搭建 Astro 骨架，验收：astro dev 能启动
2. 迁移文章 front matter，验收：脚本校验全部通过
3. 迁移主题，验收：首页和文章页视觉对照截图
4. 迁移部署脚本，验收：CI 全绿

每个目标一个会话，完成标准独立可验证。串起来就是一条没人盯着也不会走偏的流水线。
